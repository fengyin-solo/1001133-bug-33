# 市政道路桥梁养护管理平台

覆盖道路巡查、桥隧定检、路面病害、交安设施、绿化管养、除雪防汛及养护工程管理的市政道桥全要素养护后台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

### 伸缩缝成组更换

更换一组伸缩缝以前分散在材料预占、缝台账、施工工作台三处，进度各自维护、对不上且重试会重复建单；
现在统一收在 `app/services/replacement.py`（路由前缀 `/api/replacements`）：

- 三阶段单向推进：`POST /submit`（预占新材料）→ `POST /assess`（安全评估排序）→ `POST /confirm`（更换落账）。
- 任务按「施工批次号」幂等：重复提交/评估/落账回显既有结果，不重复预占、建单、扣料。
- 阶段推进与物资预占/释放在 `store.transaction()` 单事务内提交，失败整体回滚；
  `store.batch_advance(批次号)` 让同批次并发串行，只允许一个批次推进，不同批次可并行。
- 安全优先顺序以评估意见为准（紧急 > 严重 > 一般，同档按缝编号），施工工作台据此排序。
- 落账把更换结论回写缝台账（缝详情读同一行），但不覆盖既有「当前缝宽」。
- 旧材料占用在落账时迁移释放；物资清单返回「可用数量 = 库存数量 − 预占数量」。
- 单缝动作只保留清理堵塞、修补锚固；「更换伸缩缝」一律走成组更换批次，避免再出现第三条推进路径。
- 后端服务层仅依赖标准库，可用 `cd backend && python3 -m unittest discover -s tests -v` 离线验收。
